# Cloud campaigns

Every experiment reported from the multi-host testbed is driven by one of these scripts.

They exist because the original campaign scripts were generated ad hoc with host addresses
substituted in, and lived only on the operator's machine — so the newest and most contested
results in the manuscript could not be regenerated by anyone, including us. That directly
contradicted the paper's availability statement.

## Running

```bash
cp cloud/hosts.env.example cloud/hosts.env   # fill in private IPs
bash cloud/campaigns/concurrency.sh
```

`common.sh` resolves hosts, the plans directory and the pipelining flag, and is sourced by
every campaign. `hosts.env` is gitignored: addresses are ephemeral per provisioning.

These manipulate the machine rather than replaying against it, and several need `sudo`.
Section 5b of [`../../reproducibility/README.md`](../../reproducibility/README.md) gives the
analysis command for each.

| script | arm | what it manipulates |
|---|---|---|
| `stamping_priority.sh` | E-A5 | stamping-thread occupancy at **fixed** utilisation — the decisive test |
| `load_geometry.sh` | E-A6 | where the load sits, at equal utilisation: cores free vs all duty-cycled |
| `occupancy_measured.sh` | E-A7 | measures the occupancy the earlier arms could only infer |

## Two guards worth keeping

**`p4_ack_batching.sh` aborts if the treatment does not reach the consumer.** The
acknowledgement-batching manipulation silently failed to apply three separate times in this
project — twice through shell quoting, once through an unmatched script edit — and each time
produced a null indistinguishable from a genuine refutation. The consumer additionally logs its
effective `ack_batch` to `consumer.log`, so which arm a run belongs to is recoverable from the
artefacts alone.

**`netem.sh` sets `limit 200000`.** At the default 1000 packets the shaper's own queue overflows
under our burst and TCP retransmission backoff imposes a flat multi-second stall unrelated to the
application — the shaper becomes the experiment. We tested this as an explanation for the
multi-host anomaly (1000 → 200000) and it did **not** account for it, but the guard stays.
